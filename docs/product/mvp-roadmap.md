## 1. 路线图原则

- **R1 主流程优先**：优先打通「导入 → 理解 → 档案 → 意图 → 大纲 → 剧本 → 报告」端到端可演示链路，工程细节随后补。
- **R2 数据契约先行**：先冻结 YAML Schema 与工件存储模型，再实现上层生成与编辑，避免返工（对应 FR-8 / PRD §7）。
- **R3 中间产物可编辑**：每个里程碑交付的工件都必须「可保存、可回到、可编辑」（对应 PRD P8）。
- **R4 信任能力不延后**：`source_ref` 溯源与 `ai_inferred` 标注随生成能力一起落地，不作为「后续优化」（对应 PRD P4/P5）。
- **R5 可独立验收**：每个任务有明确验收口径；main 分支在每次合入后保持可运行（AGENTS.md 硬约束）。

## 3. 里程碑详情

### M0 · 工程地基与数据契约 `Must`

打通后续所有功能的承载层。**先做，且 Schema 一旦冻结需走评审才能改。**

| 任务 | 说明 | 关联 | 验收 |
| --- | --- | --- | --- |
| M0-T1 项目骨架 | 按 README 规划建立 `app/`（import/analysis/outline/script/report/editor/settings）目录与基础路由 | — | 应用可启动，路由可访问空白页 |
| M0-T2 YAML Schema 与类型 | 依 PRD §7 定义 `screenplay` 数据模型与校验，落到 `docs/schema/` 与代码类型 | FR-8 | 单测覆盖 parse→edit→serialize **往返无损**，`source_ref`/`flag` 不丢 |
| M0-T3 工件存储模型 | 「改编项目」容器，承载理解/档案/大纲/剧本/报告各工件，自动保存与恢复 | NFR-6 | 流程中断后可恢复未保存工件 |
| M0-T4 语言三分基建 | UI / Source / Output Language 解耦，不硬编码语言假设 | NFR-7 | 数据模型与文案不含语言硬编码 |

依赖：无。**阻塞** M1–M7。

## 4. 端到端验收（MVP Demo 级）

与 PRD §10.3 一致：作者导入 3 章中文小说后，可依次获得**可编辑**的作品理解、人物档案、分场大纲、剧本初稿（YAML，含 `source_ref` 与 `ai_inferred` 标记）、改编取舍报告，并能在双栏视图中对单场执行一次自然语言局部重生成且**只改动该场**。

## 7. 风险与依赖提示

- **数据契约返工风险**：M0-T2 Schema 未冻结前，不要在 M4/M5 大量依赖具体字段；变更 Schema 需评审。
- **信任能力不可延后**：`source_ref`（M4-T2/M5-T5）与 `ai_inferred`（M5-T4）属 MVP 必做，不得降级为「后续优化」。
- **关键路径**：M5（媒介翻译）是价值核心也是最大不确定性，建议尽早投入原型验证心理外化与加戏标注效果。
- **提交约束**：每个 `M*-T*` 任务尽量对应一个独立、可运行、可验收的 PR；不混入无关重构（AGENTS.md）。
