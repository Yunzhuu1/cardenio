## 1. 设计概念：克制的戏剧（Restrained Drama）

「戏剧舞台」的气质与「冷静专业」的色彩看似有张力，本产品有意把二者统一为一个核心概念：

> **戏剧感来自结构、光与暗、聚焦与代入，而不是浓烈的色彩。**
> 我们用克制、冷静、专业的视觉语言，去承载舞台般的代入体验。

### 核心隐喻

| 隐喻                 | 在产品中的含义                                                             |
| -------------------- | -------------------------------------------------------------------------- |
| 舞台（Stage）        | 整个工作台就是一座舞台，小说在此「入戏」                                   |
| 聚光（Spotlight）    | 用光（强调色 + 专注模式）聚焦当前正在打磨的那场戏                          |
| 幕（Curtain / 幕间） | 流程的确认关卡是「幕间」——一幕落定才进入下一幕（呼应「先理解，再改编」P1） |
| 同台（On one stage） | 双栏对照：原文与剧本同台并置                                               |
| 作者即导演           | 作者始终掌控调度，AI 是副驾驶而非主角（呼应 P2）                           |

### 设计基调原则

- **D1 克制优先**：留白如空舞台；装饰服从内容，绝不喧宾夺主。
- **D2 以光聚焦**：强调与注意力靠「光」（强调色、对比、专注模式）引导，而非堆砌色块。
- **D3 冷静专业**：低饱和中性底色传达可信赖的工具感，降低 AI 协作的心理门槛。
- **D4 文学质感**：正文与剧本用衬线体，守住「创作是手艺」的尊重感。
- **D5 信任可见**：溯源、AI 来源、留白等信任能力，必须有稳定、可识别的视觉语言（见 §4.3）。

## 3. 色彩系统

色彩系统以当前 `frontend/app/app.css` 的 CSS 变量为准。视觉概念仍是「克制的戏剧」，但色值不再以传统色原值为准，而以实现层经过 OKLCH 调整和对比度校准后的令牌为准。

界面主体采用近白纸面、深冷墨字和低对比浅底；主操作使用带舞台光感的黄调强调色；信任能力使用一组独立语义色（source / inferred / todo / relation / success / warning / risk）。这些语义色可直接作为文本色，也可作为实底 chip 色使用。

> **设计判断**：用户给出的色板颜色只作为色相参考；实现令牌必须在 OKLCH 中移动到合适的 L / C 位置，以满足亮色和暗色主题下的可读性。当前语义色按 WCAG 2 AA 正文对比度校准。

### 3.5 语义色 ↔ 信任能力映射（关键）

视觉直接服务 PRD 的信任能力（P4/P5/P6）。颜色只是其一，**绝不单独依赖颜色**，必须叠加标签/图标/排版（见 §11 可访问性）。

| 信任能力                 | 视觉语言                                      | 令牌                                | 语义判断                         |
| ------------------------ | --------------------------------------------- | ----------------------------------- | -------------------------------- |
| `source_ref` 溯源        | 来源蓝 chip + 可点击来源编号，点击高亮原文    | `semantic/source`                   | 表示内容有明确原文来源，可追溯   |
| `from_source` 原文已有   | 默认呈现 + 来源蓝细下划线/边标                | `semantic/source`                   | 区分原文已有内容和 AI 新增内容   |
| `ai_inferred` AI 新增    | 推断紫标签 + 「AI」图标 + 浅高亮底            | `semantic/inferred`                 | AI 补上的内容必须被作者看见      |
| `TODO` 留白              | 留白绿虚线框 chip，可筛选定位                 | `semantic/todo`                     | 不确定处留给作者确认，不强行补写 |
| `subtext` / `mood`       | 留白绿弱化衬线 + 次要色，区别于台词正文       | `semantic/todo` / `text/secondary`  | 人物气息、潜台词和未明说的信息   |
| 人物关系线               | 关系珊瑚线条 / 节点连接，避免误认为成功或风险 | `semantic/relation`                 | 表示人物关系和结构连接           |
| 破坏性（删除/合并/冲突） | 风险橙红，需二次确认                          | `semantic/risk` / `--destructive`   | 改动会影响原文、人物或结构       |
| 作者锁定项               | 舞台光小锁 + 低饱和底                         | `accent/primary`                    | 作者明确保留，不应被自动改写     |

### 3.6 与 coss.ui / shadcn 令牌对齐

前端采用 coss.ui，配色与 shadcn/ui 兼容。shadcn 以一组语义化 CSS 变量驱动主题（`:root` 亮色、`.dark` 暗色），coss.ui 沿用同一约定。本指南的语义令牌按下表映射到 shadcn 变量；色值仍以 §3.3 / §3.4 为准。

| 本指南令牌            | shadcn 变量                                  | 说明                                                                               |
| --------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------- |
| `bg/base`             | `--background`                               | 页面底色                                                                           |
| `text/primary`        | `--foreground`                               | 主文字                                                                             |
| `bg/surface`          | `--card` / `--popover`                       | 卡片、浮层底                                                                       |
| `text/primary`        | `--card-foreground` / `--popover-foreground` | 卡片/浮层文字                                                                      |
| `accent/primary`      | `--primary`                                  | **主操作色 = 舞台光**                                                              |
| `oklch(0.2587 0.0547 74.4413)` | `--primary-foreground`        | 主按钮上的文字                                                                     |
| `bg/surface-2`        | `--secondary` / `--muted` / `--accent`       | 次级底、弱化底、hover 底（shadcn 的 `--accent` 是低对比 hover 背景，非品牌强调色） |
| `text/secondary`      | `--muted-foreground`                         | 次要/弱化文字                                                                      |
| `border`              | `--border` / `--input`                       | 描边、输入边框                                                                     |
| `semantic/source`     | `--source`                                   | 原文来源 / 溯源                                                                    |
| `semantic/inferred`   | `--inferred`                                 | AI 新增 / AI 推断                                                                  |
| `semantic/todo`       | `--todo`                                     | 留白 / 潜台词 / 人物语气                                                           |
| `semantic/relation`   | `--relation`                                 | 人物关系线                                                                         |
| `semantic/success`    | `--success`                                  | 成功 / 已确认 / 结构稳定                                                           |
| `semantic/warning`    | `--warning`                                  | 需复查 / 轻风险 / 注意提示                                                         |
| `semantic/risk`       | `--risk` / `--destructive`                   | 风险提示 / 破坏性操作                                                              |

**扩展语义令牌**：信任能力专用色（`source` / `inferred` / `todo` / `relation` / `success` / `warning` / `risk`）不在 shadcn 默认变量集内，需作为自定义 CSS 变量注册到主题（建议命名 `--source` / `--inferred` / `--todo` / `--relation` / `--success` / `--warning` / `--risk`，各带 `-foreground`），亮/暗各一套，取值见 §3.3 / §3.4。它们是本产品区别于通用模板的关键视觉资产，不可省略。

> 约定澄清：shadcn 的 `--accent` 是「悬停用的低对比背景色」，与本指南「品牌强调 / 入戏主色」概念不同。本产品的品牌强调色统一走 `--primary`，避免混淆。

### 3.8 使用比例

为避免传统色变成装饰堆砌，界面遵循以下比例：

| 色彩角色                  | 推荐比例 | 说明                                   |
| ------------------------- | -------- | -------------------------------------- |
| 近白纸面 / 深冷墨底 | 72%      | 页面、卡片、阅读底，建立工具底色       |
| 深冷墨字 / 浅文字    | 16%      | 文字、分隔、结构信息                   |
| 低对比浅底 / 次级面  | 7%       | 次级面板、hover、弱化区域              |
| 舞台光主色           | 3%       | 主操作、当前步骤、焦点                 |
| 信任语义色           | 2%       | AI 新增、风险、TODO、来源、关系线      |

### 3.9 落地边界

- 主按钮优先使用 `accent/primary`；同屏只保留一个最高权重主按钮。
- `semantic/inferred` 只表示「AI 新增/AI 推断」，不得用于普通高亮。
- `semantic/source` 只表示「有原文来源」，不得用于普通成功提示；普通成功态使用 `semantic/success`。
- `semantic/risk` / `--destructive` 用于删除、覆盖、合并、破坏人物设定等高风险操作；普通警告使用 `semantic/warning`。
- 风险色必须配合文字说明，避免只靠颜色表达危险。
- 暗色主题中风险色面积必须更克制，防止剧本编辑区产生视觉疲劳。

---

## 4. 字体系统（混排）

界面用无衬线保证现代清晰；正文与剧本用衬线，守住文学质感。

### 4.1 字族

| 角色          | 中文                                       | 西文          | 用途                                   |
| ------------- | ------------------------------------------ | ------------- | -------------------------------------- |
| UI Sans       | 思源黑体（Source Han Sans / Noto Sans SC） | IBM Plex Sans | 导航、按钮、表单、标签、菜单           |
| Content Serif | Noto Serif SC                              | Courier Prime | 原文阅读、剧本正文、对白、长文         |
| Mono          | 等距更纱黑体 SC                            | IBM Plex Mono | YAML 源码视图、`source_ref` 等技术信息 |

**关于 Content Serif 的西文 Courier Prime**：Courier Prime 是行业标准的剧本（screenplay）等宽字体，搭配 Noto Serif SC 用于剧本/正文区，会带来「打字机剧本」的专业代入感，强化产品的戏剧改编气质。需注意它是等宽体而非传统衬线体——这是有意为之的剧本质感选择，而非排版疏漏。

> 字体均为开源、可商用、中文字形覆盖完整的字族（思源/Noto 系、IBM Plex 系、Courier Prime）。引入这些字体需在 README 记录来源与授权（AGENTS.md）。CJK 字体体积较大，实现阶段需做按需子集化（subsetting）与按字重分包。

### 4.2 用法规则

- **无衬线（UI）**：所有界面操作元素、信息标签、报告中的结构化标题。
- **衬线（正文）**：原文小说、剧本场景文本、对白、给作者的注释——凡「阅读/创作内容」皆衬线。
- **等宽（Mono）**：仅 YAML 源码视图与技术性引用（章节/段落号）。
- 不在同一段落混用衬线/无衬线；以「界面 vs 内容」为分界。

### 4.3 字号与行高

中文衬线长文需要更宽松行高。基准 `16px`，模数约 1.25。

| 令牌      | 字号 / 行高      | 用途               |
| --------- | ---------------- | ------------------ |
| `display` | 32 / 1.3         | 页面主标题、空状态 |
| `h1`      | 24 / 1.35        | 区块标题           |
| `h2`      | 20 / 1.4         | 卡片/场景标题      |
| `body`    | 16 / 1.7         | UI 正文            |
| `reading` | 17 / 1.8（衬线） | 原文/剧本阅读区    |
| `small`   | 14 / 1.6         | 次要信息、标签     |
| `caption` | 12 / 1.5         | 注脚、计数         |
| `mono`    | 14 / 1.6         | YAML 源码          |

---

## 5. 间距、栅格与圆角

- **基准网格 8px**：间距取 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64。
- **圆角**：克制——`sm 4px`（标签/输入）、`md 8px`（卡片/按钮）、`lg 12px`（面板/弹窗）；不用过圆造型，保持专业冷静（D3）。
- **阴影**：极克制，仅用于浮层（弹窗、下拉）；平面优先，靠边框与底色分层。

---

## 6. 布局与「舞台」模式

- **双栏同台**：原文（左）｜ 剧本（右），滚动联动、互相高亮（FR-9.1）。这是产品的主舞台。
- **聚光 / 专注模式**：选中某场戏时，可弱化其余内容（降低对比/亮度），用 `accent/primary` 点亮当前场——像追光打在台上的演员（D2）。
- **幕间 / 确认关卡**：阶段切换（理解→档案→大纲→剧本）以「幕间」过渡承载确认动作，强化「一幕落定再进下一幕」（P1）。
- **留白即空舞台**：充分留白，让内容登场（D1）。

---

## 7. 动效

戏剧的「幕启」「追光」是概念来源，但执行要克制、专业，绝不炫技。

- **时长**：进出 160–240ms；大区块/幕间过渡 ≤ 320ms。
- **缓动**：标准 ease-in-out；强调入场可用轻微 overshoot，但幅度小。
- **聚光过渡**：专注模式切换用亮度/对比的渐变，而非花哨位移。
- **可关闭**：尊重「减少动态效果」系统偏好（reduced motion）。

---

## 8. 图标与插画

- **图标**：统一线性、等宽描边、几何克制；与 UI Sans 视觉重量匹配。
- **戏剧母题克制使用**：幕、追光、面具等元素只在 logo、空状态、引导处点到为止，不滥用。
- **空状态 / 引导**：可用极简线描的「舞台/幕」意象，配冷静色与一句鼓励文案。
- **插画**：少而精；不引入与冷静专业气质冲突的高饱和卡通风。

## 9. 组件视觉方向

| 组件                       | 视觉要点                                                                    |
| -------------------------- | --------------------------------------------------------------------------- |
| 场景卡（Scene card）       | 「台上的一场戏」；含场景标题、`source_ref` chip、来源标记；当前场被聚光强调 |
| 来源 chip（source_ref）    | 来源蓝 chip、可点击；hover 预览原文出处                                     |

| YAML 源码视图              | Mono 字体、深色代码面板（亮色主题下也用深底以区分）                         |

## 10. 明暗主题策略

- **双主题**，默认**跟随系统**，可手动切换并记忆偏好。
- 两套主题**功能与可识别性对等**：所有语义色（source/inferred/todo/relation/success/warning/risk）在明暗下都有对应令牌，对比度达标。
- 暗色不是简单反色，而是「夜戏台上的深冷墨底」——深冷背景、浅文字和高明度语义色共同保证可读性；舞台光主色仍只负责最高权重动作。

---

## 11. 可访问性

- **对比度**：正文与背景至少满足 WCAG AA（正文 4.5:1，大字 3:1）。
- **不只靠颜色**：`from_source` / `ai_inferred` / `todo` 等状态必须同时具备**标签文字 + 图标 + 形态**，色盲用户也能区分（直接服务 P5「AI 产物可区分」的有效性）。
- **键盘可达**：双栏、聚光模式、确认关卡均可键盘操作。
- **减少动态**：遵循 `prefers-reduced-motion`。

---

## 12. UI 文案语气（Voice & Tone）

- **副驾驶口吻**：克制、专业、尊重作者，不喧宾夺主，不卖弄。
- **诚实**：不确定就说不确定（对应留白 P6）；不夸大 AI 能力。
- **中文优先**：文案以中文母语者习惯书写，简洁、有分寸；避免翻译腔。
- **鼓励而不聒噪**：空状态/引导可给一句温和鼓励，但不煽情、不刷存在感。

---

## 13. 设计令牌与实现衔接

- 视觉以**设计令牌**（design tokens）形式落地。前端采用 coss.ui，因此**色彩令牌直接落到 shadcn/ui 的 CSS 变量约定**（`--background`、`--foreground`、`--primary`、`--destructive` 等，见 §3.6 映射），并补充本产品的扩展语义令牌（`--source` / `--inferred` / `--todo` / `--relation` / `--success` / `--warning` / `--risk`，各带 `-foreground`）。
- 令牌分两层：**基础调色板**（具体色值）→ **语义令牌/shadcn 变量**（用途名）。组件只引用语义变量，换主题/调色只改 `:root` 与 `.dark` 的映射。
- 字体、间距、圆角、动效时长同样令牌化，集中管理；字族通过 CSS 变量（如 `--font-sans` / `--font-serif` / `--font-mono`）绑定到 §4.1 的选定字体。
- coss.ui/shadcn 仅提供调色与组件基座；本指南的概念层（克制的戏剧、聚光、信任能力语义色）是产品独有定制，不随基座默认值走。
